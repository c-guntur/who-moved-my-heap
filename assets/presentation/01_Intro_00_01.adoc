== Why look at the heap?

[.lead]
Five JDK tools show what is on the heap, how it grows and how big each object is.

* Garbage is invisible in the code, but obvious in a class histogram.
* Fewer and smaller objects mean fewer GCs and more headroom for a spike.
* Object size depends on the JVM: compact object headers shrink most small objects.
* The tools: `jmap`, `jcmd`, `jps`, `jstat` and Java Object Layout (JOL).

[.notes]
--
The shakers benchmarks use a class histogram (`jcmd GC.class_histogram -all`) before and after each
iteration to count what every call allocates. The movers tests use JOL to measure collection footprints
with compact object headers off and then on.
--
