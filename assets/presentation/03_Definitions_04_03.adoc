== Where the 4 bytes matter

image::diagram-04-object-headers.svg[HashMap$Node 32 B vs 24 B,role=diagram]

* An object only shrinks if it then fits a smaller 8-byte boundary.
* Less heap and less GC work for object-heavy data.

[.notes]
--
Compact headers trim the JDK stream garbage by 16 to 24 B per call (7 to 11%); the object count stays
the same. Not allocating at all saves the whole 160 to 224 B.
--
