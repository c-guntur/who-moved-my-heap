== Object pooling: pool resources, not small objects

[.track]
Intro · Problem · Definitions · [.on]#Solutions# · AI skills · Wrap-up

[.lead]
A pool pays off for costly objects; for small ones, allocate fewer instead.

* Pool threads, connections and direct buffers.
* The JDK already pools `Integer` -128 to 127 through `Integer.valueOf`.
* For small objects: presize collections, use primitives, avoid boxing.
* A pooled object lives long, gets promoted, and needs locking.
