== Non-capturing lambdas

[.track]
Intro · Problem · Definitions · [.on]#Solutions# · AI skills · Wrap-up

[source,java]
----
// capturing: a new lambda on every call, holding the value
Iterate.anySatisfy(list, Integer.valueOf(test)::equals);

// fat-free: one constant lambda, the value is a parameter
Iterate.anySatisfyWith(list, Integer::equals, test);
----

* Escape analysis off: 32 B capturing, 16 B fat-free (only the `Integer` box).
* Move captured values into parameters: the `*With` methods.

[.notes]
--
⏱ 32:35, stay about 45 s. Solutions: 24:00 to 34:00 (10 min).

With escape analysis on, both EC calls are 0 B. The JDK stream has no `*With` form: even a non-capturing predicate
leaves its 176 B pipeline behind. In EC 13.0.0, `ImmutableList.anySatisfyWith`, `countWith` and `detectWithIfNone`
go through `Predicates.bind`, so they are not fat-free.
