== Why look at the heap?

[.track]
[.on]#Intro# · Problem · Definitions · Solutions · AI skills · Wrap-up

[.lead]
A few JDK tools and one library show what is on the heap of a running JVM.

* Garbage is invisible in the code, but obvious in a class histogram.
* Fewer and smaller objects mean fewer GCs and more headroom for a spike.
* `jps` finds the JVM.
* `jmap` and `jcmd` look inside it.
* JOL, a library, measures object sizes
* JMH - to measure garbage per call (covered later).
