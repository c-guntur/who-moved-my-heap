== Two heaps in one

[.track]
[.on]#Appendix#

[.lead]
A heap has a baseline that stays and a volatile part that churns.

* Baseline: the live objects your collections hold between calls.
* Volatile: short-lived garbage that each call allocates and drops.
* The baseline sets the floor; the volatile part sets how often GC runs.
* Both have to fit under `-Xmx` at the busiest moment.

[.notes]
--
The movers measure the baseline: JOL retained size of a filled collection.
The shakers measure the volatile part: bytes per call (`gc.alloc.rate.norm`), GC runs per billion calls,
and exact object counts per call from class histograms.
--
