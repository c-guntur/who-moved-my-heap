== Watching garbage with `jstat -gc`

[.track]
[.on]#Appendix#

[.lead]
`-gc` shows the same counters in KB, so eden size and GC count give a rough allocation rate.

[source,text]
----
$ jstat -gc <pid> 1s 3                    (columns trimmed, sizes in KB)
       EC          EU          OU     YGC     YGCT
 124928.0     35840.0      2180.4      14    0.120
 125952.0    115712.0      2180.4      15    0.125
 130048.0     61440.0      7300.4      17    0.135
----

* `EU` climbs towards `EC`, a young GC runs, and eden starts again: a sawtooth.
* Eden capacity times young GCs per second is roughly the allocation rate: about 125 MB × 1.5/s ≈ 190 MB/s.
* `jstat -gccause` adds the cause of the last GC, here `G1 Evacuation Pause`.

[.notes]
--
Same program as the Intro `jstat` slide (JDK 25, G1, `-Xmx256m`). The rate is an estimate: it assumes eden is
full at each GC and ignores what survives. JMH's `gc.alloc.rate` is the measured value; the shakers report it.
--
